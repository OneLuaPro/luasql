# Scenario `params`

Checks how prepared statements keep their parameters between executions: what runs without new parameters, with too few or too many, with variable arguments, with parameters that are not valid, after `stmt:reset()` and after a full garbage collection (GC). A program that executes the same statement thousands of times relies on this. Behavior of the client library (with Oracle: OCI, the Oracle Call Interface) that a user would not expect is a known limitation with its reason (`backend.paramsLimits`). Eight phases then run bind loops as leak checks, also for `conn:execute` with parameters.

A parameter is a plain Lua value, bound by its Lua type, or a pair `{value, type}` with a constant of `luasql.type`. `stmt:execute()` runs with the values bound, `stmt:execute{…}` (one table) takes a parameter table, every other call takes variable arguments by position, where `nil` is NULL. `conn:execute(sql, …)` takes parameters in the same forms.

Errors are checked against the [error convention](../README.md#error-convention): an error of the DBMS gives `nil` and a message, a misuse of the API raises an error of LuaSQL. Too many parameters in a table, a placeholder without a value and a wrong number of variable arguments give `nil` and a message: whether they are right depends on the SQL. With Oracle the first two come from OCI, the last from `luasql.oci8`, which compares the number of arguments with the parameters OCI reports (`backend.argCountError`).

The scenario is skipped if the driver has no `conn:prepare`; the reset cases are skipped if it has no `stmt:reset()`; `nameThenPosition` and `spellings` are skipped without `backend.paramsNamedQuery`, `argCount` without `backend.argCountError`, `connDml` without `backend.paramsDmlBlock`.

## Cases

Each case runs once, on a statement of its own.

| Test              | Checks                                                                                                                                       | Results                                                                                                                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `neverBound`      | `stmt:execute()` on a statement with a placeholder that was never bound.                                                                     | Pass: `nil` and `ORA-01008` (not all variables bound). Fail: success, a crash or another error.                                                                                          |
| `keepAfterBind`   | Binds 42, then executes with `execute()` and `execute({})`; then with `execute(nil)` and again with `execute()`.                            | Pass: the first two return 42, the value bound last; `execute(nil)` binds NULL, and `execute()` keeps it. Fail: an error or another value.                                                |
| `partialParams`   | Binds two placeholders, then executes with a table that holds only the first.                                                                | Pass: 3, 2: the table binds only the first placeholder, the second keeps its value, as LuaSQL defines it for all drivers. Fail: `nil` and an error, or any other result. |
| `tooManyFresh`    | Executes a statement with one placeholder with two parameters, then with one.                                                                | Pass: the first call gives `nil` and `ORA-01036`, the second returns the new value. Fail: the first call succeeds, or the statement is unusable afterwards.                                |
| `failedBindKeeps` | Binds 7, executes with two parameters (8, 9), which must fail, then executes without parameters.                                             | Pass: the failed call leaves 7 bound. Limit: 8 is bound, because OCI binds one parameter after the other and the error comes with the second. Fail: anything else.                        |
| `varArgs`         | `execute(5)`, `execute()`, `execute(5, 6)` and `execute()` on one placeholder; `execute(1, 2)`, `execute(5)` and `execute()` on two; `conn:execute(sql, 9)`, `conn:execute(sql, {9})` and `conn:execute(sql, 1, 2)`. | Pass: one argument binds by position and stays bound; a wrong number of arguments gives `nil` and a message, and the values bound before stay (5, then 1 and 2); `conn:execute` gives 9 twice and `nil` for two arguments. Fail: anything else. |
| `nameThenPosition` | Binds `{a = 5}` to a named placeholder, then `{7}` by position, then executes without parameters.                                          | Pass: 5, 7 and 7. Fail: an error or another value.                                                                                                                                         |
| `typedNull`       | Binds 42, then `{null, int}`, then executes without parameters; `{null, binary}` on a string query.                                         | Pass: 42, then NULL three times. Fail: an error or another value.                                                                                                                          |
| `mixedKeys`       | Binds 42, then executes with a table of positional and named keys.                                                                           | Pass: the call raises an error of LuaSQL; afterwards `execute()` still returns 42 and a new bind works. Fail: the call succeeds or returns an error, or something of the table was bound. |
| `badKey`          | The same with keys that are neither a string nor a positive integer: `0`, `1.5`, `true`.                                                     | As above.                                                                                                                                                                                  |
| `notPair`         | The same with tables that are no pair `{value, type}`: a pair without type, three elements, the type as a string.                           | As above.                                                                                                                                                                                  |
| `unknownType`     | The same with type constants that `luasql.type` does not have: -1, 7 (the number `luasql.type.null` had before it became a value of its own) and the largest constant plus one. | As above.                                                                                                                                                         |
| `typeMismatch`    | The same with values that do not match their type: a string, 3.7 and a table as `int`, a number as `string`, `boolean`, `timestamp` and `binary`, a boolean as `number`. | As above.                                                                                                                                                             |
| `unbindable`      | The same with Lua values that cannot be bound: a function, a thread, a userdata and an empty table in a parameter table; a function, a userdata and a table as variable arguments. | As above.                                                                                                                                                     |
| `stringAfterGc`   | Binds a string that exists nowhere else, runs a full GC, fills the freed memory with other strings, then executes without parameters.       | Pass: the original string comes back. Fail: a wrong string or a crash: the driver did not keep its own reference to the bound string.                                                     |
| `resetClears`     | Binds 42, calls `stmt:reset()`, then executes without parameters, then with a new one.                                                      | Pass: execute without parameters gives `nil` and `ORA-01008`, the new bind works. Fail: the old value is still bound, or the statement is unusable.                                       |
| `resetUnbound`    | Calls `stmt:reset()` on a statement that was never bound, then binds.                                                                        | Pass: reset succeeds and the bind works. Fail: an error.                                                                                                                                   |
| `resetOpenCursor` | Calls `stmt:reset()` while a cursor of the statement is open; then closes the cursor and resets again.                                      | Pass: the first reset raises an error of LuaSQL, the second succeeds and drops the bindings. Fail: the first reset succeeds, returns an error or crashes, or the second does not clear the bindings.                    |

## Phases

Iterations per phase: smoke 500, standard 10 000, nightly 100 000.

| Phase         | Each iteration                                                                                                                                                              | Fails when                                                                                       |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `reuseBinds`  | binds a new integer, then executes again, in turn as `execute()`, `execute(i)` and `execute({})`                                                                            | the value bound last does not come back, or a counter or the memory grows (see [Phases](../README.md#phases)) |
| `rebindReset` | binds a string of changing length (1 to 300 characters) and a timestamp with fractional seconds; a full GC every 50th iteration, execute without parameters every 3rd, `stmt:reset()` every 5th | a value comes back wrong, or a counter or the memory grows                                      |
| `rejectedTables` | executes with one of the parameters of the cases `mixedKeys` to `unbindable`, one after the other; every 10th iteration binds a new integer and reads it back | a call does not raise an error of LuaSQL, the integer does not come back, or a counter or the memory grows: an error raised after something was allocated leaks it |
| `plainValues` | binds a plain value and reads it back, in turn: an integer, an integer above 2^53 (2^53 + i), a float, a string, a boolean, `luasql.type.null` and `nil`; in a table or as a variable argument | a value comes back wrong (a boolean comes back as the text it is bound as, `backend.boolText`), or a counter or the memory grows |
| `argCount` | in turn: two arguments for one placeholder, one for two, `conn:execute(sql, i, i)` for one placeholder, `conn:execute(sql)` without a value; every 10th iteration a valid execute of both statements | a call does not give `nil` and a message, the values bound before do not stay, or a counter or the memory grows |
| `connQuery` | `conn:execute` of a query with a string and a timestamp, in a table or as variable arguments in turn; the cursor is read to its end, closed after the row, or dropped without close, in turn; a full GC every 10th iteration | a value comes back wrong, or a counter or the memory grows: the bindings belong to the cursor until it is closed, also by the GC |
| `connDml` | `conn:execute` of a PL/SQL block (not a query) with a timestamp and a number, in a table or as variable arguments; every 5th iteration a string that is not a number fails at the execute | the call does not return a number of rows, the failing one does not give `nil` and the error, or a counter or the memory grows |
| `spellings` | binds one named placeholder as `a`, `:a`, `A` and by position, in turn | the value does not come back, or a counter or the memory grows. `luasql.oci8` keeps one binding per spelling until `stmt:reset()` or `stmt:close()`; there are only four, so the memory must stay flat |
