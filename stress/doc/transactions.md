# Scenario `transactions`

Checks autocommit, commit and rollback: what another session sees, what a failed statement or DDL (Data Definition Language) does to an open transaction, the row counts of DML (Data Manipulation Language), and what happens to an open transaction when its connection is closed. Then it runs transaction loops as leak phases.

"Another session" is the admin connection: it sees only committed rows. Cases that need it are skipped without one. Behavior of the DBMS or the driver that a user might not expect is reported as a limit with its reason.

The scenario uses a table `luastress_tx` (`id NUMBER PRIMARY KEY, v VARCHAR2(100)`); it is skipped if the backend has none or the driver has no `conn:prepare`.

## Cases

Each case runs once. Every case starts with autocommit on, no open transaction and an empty table; this state is restored after each case, also after a failure.

| Test                  | Checks                                                                                                                                                                       | Results                                                                                                                                                       |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `autocommitVisible`   | Autocommit on: inserts a row.                                                                                                                                                | Pass: another session sees the row at once. Fail: it does not. Skipped without the admin connection.                                                          |
| `manualInvisible`     | Autocommit off: inserts a row.                                                                                                                                               | Pass: the own session sees it, another one does not. Fail: the row is missing in the own session or visible to another one before commit. Skipped without the admin connection. |
| `manualCommit`        | Autocommit off: inserts a row and calls `conn:commit()`.                                                                                                                     | Pass: another session sees the row. Fail: it does not. Skipped without the admin connection.                                                                  |
| `manualRollback`      | Autocommit off: inserts a row and calls `conn:rollback()`.                                                                                                                   | Pass: the row is gone, in the own session and, if the admin connection is there, for another one. Fail: the row is still there.                               |
| `enableAutocommit`    | Autocommit off: inserts a row, then calls `conn:setautocommit(true)` with the transaction still open.                                                                        | Pass: the row is kept (committed). Limit (Oracle): `setautocommit(true)` rolls back the open transaction, the row is lost without a message.                  |
| `preparedFollowsMode` | Prepares an insert while autocommit is on, turns autocommit off and executes it; rolls back, turns autocommit on and executes it again.                                      | Pass: the first insert is not committed, the second one is: a statement follows the mode at execute time, not at prepare time. Fail: otherwise. Skipped without the admin connection. |
| `errorKeepsWork`      | Autocommit off: inserts row 1, inserts row 1 again (duplicate key), inserts row 2, commits.                                                                                  | Pass: the duplicate fails, rows 1 and 2 are there: a failed statement undoes only itself. Fail: the duplicate is accepted, or a row is lost.                   |
| `errorThenRollback`   | Autocommit off: inserts row 1, a duplicate fails, `conn:rollback()`.                                                                                                         | Pass: row 1 is gone. Fail: it is still there.                                                                                                                 |
| `ddlCommits`          | Autocommit off: inserts a row, runs DDL (`CREATE TABLE`), rolls back.                                                                                                        | Pass: the row is gone. Limit (Oracle): Oracle commits an open transaction implicitly at DDL, also with autocommit off; the row stays.                         |
| `savepoint`           | Autocommit off: inserts row 1, sets a savepoint, inserts row 2, rolls back to the savepoint, commits.                                                                        | Pass: row 1 is there, row 2 is not. Fail: otherwise.                                                                                                          |
| `stmtAcrossCommit`    | Autocommit off: one prepared insert, executed for row 1, commit, row 2, rollback, row 3, commit.                                                                             | Pass: the statement stays usable across `commit()` and `rollback()`; rows 1 and 3 are there, row 2 is not. Fail: an error or wrong rows.                     |
| `rowCounts`           | Row counts of `conn:execute`: insert (1), `INSERT ... SELECT` (5), update of all rows (6), update of no row (0), delete (3); of `stmt:execute`: insert (1), delete of no row (0), delete (3). | Pass: every count is right, also 0. Fail: a wrong count.                                                                                                      |
| `rowCountType`        | The row count of an insert through `conn:execute` and through `stmt:execute`.                                                                                                | Pass: both are Lua integers. Fail: a float or another type.                                                                                                   |
| `plsqlAutocommit`     | Autocommit on: a PL/SQL block with an `INSERT`.                                                                                                                              | Pass: another session sees the row: a PL/SQL block is committed like a single statement. Fail: it does not. Skipped without the admin connection.             |
| `closeOpen`           | Opens another connection, inserts a row with autocommit off and calls `conn:close()`.                                                                                        | Pass: the row is not committed. Fail: closing committed the open transaction. Skipped without the admin connection.                                           |
| `gcOpen`              | The same, but the connection is left to the garbage collector (GC).                                                                                                          | As `closeOpen`.                                                                                                                                               |
| `closeVariable`       | The same, with the connection in a to-be-closed variable (`<close>`) that goes out of scope.                                                                                 | As `closeOpen`.                                                                                                                                               |

The last three cases matter because Oracle commits an open transaction when a session ends: the OCI documentation says so for `OCISessionEnd()`, and `OCILogoff()` ends the session in the same way. `luasql.oci8` therefore rolls back before it logs off, in `close`, `__gc` and `__close` alike, so only changes the program committed are kept. Before this rollback was added to the driver, these three cases showed the committed changes on Oracle 23.26.

## Phases

Iterations per phase: smoke 500, standard 10 000, nightly 100 000.

The phases run with autocommit off and one prepared insert. Besides the usual server counters they count the open transactions of the test session (`open tx`, from `v$transaction`). Before each phase a precheck opens a transaction and checks that this counter sees it; otherwise the phase fails as invalid, because "open tx 0 → 0" would test nothing. Without the admin connection the precheck and the server counters are left out.

| Phase            | Each iteration                                                                                                                          | Fails when                                                                                                                                         |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `insertCommit`   | inserts a row, commits                                                                                                                  | a call fails, the table does not hold one row per iteration at the end, or a counter or the memory grows (see [Phases](../README.md#phases))     |
| `insertRollback` | inserts a row, rolls back                                                                                                               | as above; the table must be empty at the end                                                                                                       |
| `toggleAuto`     | turns autocommit on in even, off in odd iterations and inserts a row; of the odd iterations every second one commits, the other rolls back | as above; the table must hold exactly the rows inserted with autocommit or committed                                                           |
| `errorRollback`  | inserts a row whose key exists (committed before the phase), rolls back                                                                 | the duplicate is accepted, the table does not hold exactly that one row at the end, or a counter or the memory grows                              |
